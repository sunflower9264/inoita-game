# GM（调试）模式

默认关闭的开发工具：完成任务、穿墙、改角色状态，并把当前状态直接上报到服务器——手机上没有控制台也能交出可查的现场。手机报错收集见[诊断说明](diagnostics.md)。

## 一份实现，两条通道

```
src/debug/gm-actions.ts      唯一实现（只依赖纯逻辑模块，不引入 Phaser/UI）
  ├── src/ui/panels/gm-panel.ts  人：游戏内「系统 → 调试」面板（触摸）
  └── globalThis.gm          agent：浏览器里经 CDP 驱动
```

两条通道调的是同一份代码，所以「agent 验过的」与「人点的」是同一件事。**`gm-actions.ts` 不得引入 Phaser 或 UI 模块**——测试直接 import 它，引入后无引擎的单元测试就断了（`tests/gm-actions.test.ts`）。

## 打开与关闭

| 方式 | 作用范围 | 用途 |
|---|---|---|
| 点击标题页右下角的版本号 | 写进本地存储，刷新后仍是开 | 手机（没有键盘） |
| 地址加 `?gm` | **仅本次会话**，不写存储 | 桌面、agent、自动化 |

打开后标题页角落常驻一行「调试：开」；关闭时这行不存在、系统页也没有「调试」入口——**开关关闭时不装配动作层**，`globalThis.gm` 与 `app.gm` 都不存在，所以「默认关闭」是结构上的保证，不靠调用方自觉。

## 面板与浏览器通道

**游戏内面板**：点击版本号打开开关 → 进游戏 → 「系统」页多出「调试」。面板里的结果就地显示，不弹结果框。

面板现有四个子页：

- **状态**：地图与坐标、任务与剧情计数、最近操作；[上报当前状态]、[脱困]；另有[完成任务]、[穿墙]、[2 倍速度]。有等待中的剧情战斗时，[完成任务]会先按打赢结算战斗，再由剧情事件结算战斗并接取后续任务；当前显示的任务与战斗无关时，优先处理战斗，不直接完成该无关任务。
- **人物**：选择主角或上阵伙伴，查看等级／经验／HP／MP；[升一级]（只升不降）、[回满 HP]、[回满 MP]、[全队回满]；对选中角色独立切换[无敌]、[无限蓝]、[技能无 CD]与[一击必杀]；另有[技能全满]和全局开关[升级10技能点]（开启后主角与手动佣兵每次升级获得 10 个技能点，关闭恢复每级 1 个，已获得的点数保留）。倒下的角色点[回满 HP]会走战斗侧复活。
- **道具**：按分类（全部／装备／消耗／材料／任务）浏览可发放物品；装备按短剑、长剑、布甲等种类连续分组，同组内等级从低到高。整页用滚轮或拖动滚动；点击物品格会弹出与背包一致的详情层，点右上角关闭。选中一件后用 `-10/-1/+1/+10/+100` 调整数量，[加入背包] 发放；底部可加金币（+1万／+10万／+100万）。列表排除只能地面拾取的物品。
- **任务**：可以按剧情顺序浏览 230 个任务组，也可以搜索任务名或组名。任务详情显示所选现场、需要准备的进度和接取演出。点击跳转后，先选手动槽保存当前进度。保存成功才执行刚才预览的计划，离开存档页会取消。

「圣女救援行动」按「潜入艾伦尼城」「艾伦尼士兵的奇袭」「单独潜入」「逃出艾伦尼城」排列。「单独潜入」有两个现场。选「独自进城救人」可从莱曼交代任务开始，自己进城开机关。选「已救出圣女，返回与莱曼汇合」会到达救人后返回的城内位置，沿已打开的通路走回莱曼处即可继续。「前往卡姆兰秘密基地」保留自己的接取演出。回广场的剧情从「追击圣女的护卫骑士」进入。

目录顺序只用于显示。调试器根据接取条件、正式交接和所选阶段准备任务、人物与机关。对话任务接取后可以直接交付，所选阶段会使用对应交付地点。演出实际启动、任务达到预期状态后，跳转才会报告成功。演出需要战斗时，等战斗及其续播结束才恢复自动存档。如果目标任务在战后已经交付，也会显示跳转成功。要回到跳转前，可以读取手动槽。

跳到「分毫之差」时，「消失的圣女1」已经交付，「消失的圣女2」仍在进行。跳到「消失的圣女3」后，「通过蜘蛛洞穴」和「坤特的狼狗」都已完成，读档折返「蜘蛛巢穴2」时可以安全通过。跳回「通过蜘蛛洞穴」时，可以重新迎战蜘蛛女王，之后的主线和支线也会按原来的条件开放。

调试器按目标任务推导的历史恢复人物位置、机关、剧情物品和战斗结果。回跳保留实际取得的经验、金币和普通装备。可重复的任务继续按游戏规则循环。

调试跳转只重放到达所选任务阶段所必需的事件和交接。与目标无关的区域、进图、近身和战斗触发不会因为「条件已经满足」被提前记为完成，也不会重建这些偶然产生的世界状态。这是调试跳转与完整跑图的有意差异；跳转后的目标现场仍按正式任务、剧情和摆放条件继续推进。

传送期间会暂时暂停自动演出。抵达后，接取剧情与后续的区域、近身和任务触发都交给正式剧情流程处理。临时用于接取的强制状态会在交接时清掉，此后的任务、物品和位置按正常游戏保存。

**agent，有浏览器**（只在必须看画面时）：开 `?gm`，然后

```js
gm.digest()        // 与面板、上报同一份摘要
await gm.report()  // 摘要 + 最近操作上报到诊断端点
render_game_to_text()   // GM 打开时返回的就是 digest()，含实时玩家坐标
```

## 状态上报

面板的「状态」页与 `gm.report()` 会把**摘要 + 最近 40 条 GM 操作**发给既有的报错收集端点（`/__diagnostics/report`，见 `tools/diagnostic-collector.mjs`）。`gm-state` 属于运行记录，落到 `.diagnostics/client-session.jsonl`；错误、警告、恢复和加载失败进 `client-errors.jsonl`。排查时用 `npm run diag:session -- <会话 id>` 看完整时间线，没有会话 id 的 GM 记录在「(无会话)」分组里。

端点单条上限 12 KB，所以摘要是**摘要**：超出时逐级丢掉最占体积的列表（操作日志→世界实体→世界标记与选择→任务列表→已完成事件）并在返回值里说明已裁剪。`.diagnostics/` 由 4014 打包静态服务与 4003 开发服务共同写入；手机验收走 443 的 HTTPS 入口，由 nginx 转发到 4014。

## 调试开关的生命周期

`无敌`、`无限蓝`、`技能无 CD`、`一击必杀`、`升级10技能点`、`穿墙` 和 `2 倍速度` 是**运行时调试开关**，不进入 `SessionState`／`WorldCombatState`／`CombatCooldownState`：

- 不写存档；
- 同一次页面会话内跨地图保留（无敌、无限蓝、无 CD、一击必杀、升级10技能点存在 `Session` 上；穿墙和倍速存在 `app` 上，换图重建 `WorldCombat` 都不会丢）；
- 刷新页面或新建会话后消失。

## 已知限制

- 无敌只拦战斗 HP 伤害（`CombatConditions.canLoseHealth` 门）；无限蓝独立控制 MP 扣除（`losesMana` 门与技能耗蓝）：开启后技能免费且免疫吸蓝；状态、增益等其它非伤害效果照常结算；剧情命令直接改血、GM 自己的回血仍会生效，不是全局免伤。
- 开启「升级10技能点」后，主角与手动佣兵后续每次升级产生的额外技能点会写入角色既有额外技能点字段（随存档正常保存），关闭开关或读档后不会回扣已有技能点。
- 道具页排除只能地面拾取的物品；这类由动作层过滤。
- 全队回满会尝试复活倒下角色，但复活表现依赖战斗场景；没有战斗场景时只回满存活成员，并在结果里说明。
- 摘要是给人看现场的**摘要**，不是全量存档；要完整状态用存档槽。
- 普通 GM 修改直接落在当前会话，正常保存会写进存档。打开开关会让 GM 代码进入运行时；关闭时不装配动作层。

## 画面恢复（WebGL）

浏览器切到后台、驱动重置或显存被回收时，WebGL 上下文会丢失。Phaser 会重新创建着色器、缓冲区和普通图片纹理；项目额外在 `restorewebgl` 事件里重画两类只有显存副本的内容：

- 衣柜用 `DynamicTexture` 合成的人物外观，按原纹理键重画，角色和动画不需要重建；
- 滚动区的静态遮罩，标记为需要重做一张遮罩纹理。

诊断会记录 `webgl-context-lost` 和 `webgl-context-restored`。如果只看到丢失、没有恢复，通常说明整个页面进程被系统杀掉了，需要重新打开；这时只能靠本地存档恢复进度。
