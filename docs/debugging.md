# GM（调试）模式

默认关闭的开发工具：跳到任意任务的调试现场、传送、改任务与角色状态，并把现场状态直接上报到服务器——手机上没有控制台也能交出可查的现场。手机报错收集见[诊断说明](diagnostics.md)。

## 一份实现，两条通道

```
src/debug/gm-actions.ts      唯一实现（只依赖纯 domain 模块）
  ├── ui/phaser/gm-panel.ts  人：游戏内「系统 → 调试」面板（触摸）
  └── globalThis.gm          agent：浏览器里经 CDP 驱动
```

两条通道调的是同一份代码，所以「agent 验过的」与「人点的」是同一件事。**`gm-actions.ts` 不得引入 Phaser 或 UI 模块**——测试直接 import 它，引入后无引擎的单元测试就断了（`tests/gm-actions.test.ts`）。

## 打开与关闭

| 方式 | 作用范围 | 用途 |
|---|---|---|
| 点击标题页右下角的版本号 | 写进本地存储，刷新后仍是开 | 手机（没有键盘） |
| 地址加 `?gm` | **仅本次会话**，不写存储 | 桌面、agent、自动化 |

打开后标题页角落常驻一行「调试：开」；关闭时这行不存在、系统页也没有「调试」入口——**开关关闭时不装配动作层**，`globalThis.gm` 与 `app.gm` 都不存在，所以「默认关闭」是结构上的保证，不靠调用方自觉。

## 面板与浏览器通道

**游戏内面板**：点击版本号打开开关 → 进游戏 → 「系统」页多出「调试」。面板里的结果就地显示，不弹结果框。

面板现有四个子页：

- **状态**：地图与坐标、任务与剧情计数、最近操作；[上报当前状态]、[记一个状态标记]、[回到状态标记]、[脱困]。
- **人物**：选择主角或上阵伙伴，查看等级／经验／HP／MP；[升一级]（只升不降）、[回满 HP]、[回满 MP]、[全队回满]；对选中角色切换[无敌]与[技能无 CD]。倒下的角色点[回满 HP]会走战斗侧复活。
- **道具**：按分类（全部／装备／消耗／材料／任务）浏览可发放物品，整页用滚轮或拖动滚动；点击物品格会弹出与背包一致的详情层，点右上角关闭。选中一件后用 `-10/-1/+1/+10/+100` 调整数量，[加入背包] 发放；底部可加金币（+1万／+10万／+100万）。列表排除只能地面拾取的物品。
- **剧情**：左侧是从 `campaign.debugStory.tasks` 列出的可调试任务；顶部可按全部／主线／支线／隐藏筛选。选中后右侧显示任务标题、当前进度、任务说明和地点。底部[进入任务]会先套用现场表（还原开演前的世界），再切到落点并由正式导演直接播该任务的开幕演出；进入后任务日志只显示这一个任务，自动存档暂停，面板顶部出现[结束调试]。预览准备期间或失败时按钮不可用，失败原因就地显示。筛选、选中项和列表滚动位置会保留；界面只用中文名称，内部标识仅用于日志。

传送与任务改写还没进面板，走同一条动作层的后续阶段。

**agent，有浏览器**（只在必须看画面时）：开 `?gm`（隐含 `?inspect`），然后

```js
gm.digest()        // 与面板、上报同一份摘要
gm.mark('before')  // 出事前存一下
gm.recall('before')// 倒回来做 A/B
render_game_to_text()   // GM 打开时返回的就是 digest()，含实时玩家坐标
```

## 状态上报

面板的「状态」页与 `gm.report()` 会把**摘要 + 最近 40 条 GM 操作**发给既有的报错收集端点（`/__diagnostics/report`，见 `tools/diagnostic-collector.mjs`），落到 `.diagnostics/client-errors.jsonl`。排查者 `tail` 这个文件即可，手机端不用复制长文本。

端点单条上限 12 KB，所以摘要是**摘要**：超出时逐级丢掉最占体积的列表（操作日志→世界实体→任务列表→已完成事件）并在返回值里说明已裁剪。`.diagnostics/` 由 4002 打包静态服务与 4003 开发服务共同挂载——手机验收走的正是 4002 打包服务。

## 调试开关的生命周期

`无敌` 与 `技能无 CD` 是**运行时调试开关**，不进入 `SessionState`／`WorldCombatState`／`CombatCooldownState`：

- 不写存档，也不随 `mark`/`recall` 回退；
- 同一次页面会话内跨地图保留（开关存在 `Session` 上，换图重建 `WorldCombat` 不会丢）；
- 刷新页面或新建会话后消失；
- headless 会话没有战斗场景：`invincible` 会明确返回失败，`no-cooldown` 可以设置但没有可观察的战斗表现。

## 已知限制

- 无敌拦战斗 HP 伤害（`CombatConditions.canLoseHealth` 门）与 MP 扣除（`losesMana` 门）：技能费用和吸蓝都不扣 MP；状态、增益等其它非伤害效果照常结算；剧情命令直接改血、GM 自己的回血仍会生效，不是全局免伤。
- 道具页排除只能地面拾取的物品；这类由动作层过滤。
- 全队回满会尝试复活倒下角色，但复活表现依赖战斗场景；没有战斗场景时只回满存活成员，并在结果里说明。
- 摘要是给人看现场的**摘要**，不是全量存档；要完整状态用存档槽。
- `mark`/`recall` 走 `Session.restoreState`（带完整校验），所以回到标记点会连同之后的任务、背包、世界状态一起回退——这正是 A/B 想要的，但别指望它只回退一项。
- GM 的改动直接落在当前会话上，之后正常保存会把改动写进存档。退路是命名标记，或读回最近存档。
- 打开开关会让 GM 代码进入运行时；关闭时不装配动作层。


## 任务级调试入口

选中一个任务，GM 把世界还原成这段剧情**开演前**的样子，再由正式导演直接播这段演出。

**现场表** `campaign.debugStory.tasks[].start` 回答「开演前世界是什么样」：任务做到哪一步、谁在哪张图、哪些门开了、背包里有什么、哪些事件已经发生。`campaign.debugStory` 是随游戏发布的调试任务目录，现场表只存与干净会话不同的部分；运行时 `prepareTaskStart` 把它展开成完整状态，走真实 `restoreState` 校验后安装，并复核安装结果是 `refresh` 固定点。主角成长、技能、金币、普通背包和已有伙伴从当前会话合并。现场表是生成物：改过 `public/content` 后运行 `npm run debug-start` 重新生成，`npm run debug-start:check` 只检查是否过期；路线、脚本草稿等输入在 `tools/debug-start/data/`。

**演出** `debugStory.tasks[].play` 回答「把哪段剧情演出来」：进入任务后由正式导演从记录的脚本/节点开演，对白、选项、战斗都用真实表现，接取和推进由演出自己完成。现场表停在开幕之前，所以可接取任务进去后仍是「可接取」，导演一开演就接取。两者分开：现场表不决定演不演，演出也不负责补人物。

**任务日志**在调试期间只显示当前任务（`debugFocusQuest` 覆盖隐藏与可见性规则）。**调试现场不写玩家存档**：进入时暂停自动存档与检查点，面板顶部出现[结束调试]；结束后清焦点、恢复自动存档并重抓一次检查点。
