# 手机报错与运行日志

打开游戏入口（`https://catgo.online:4002/` 或 4003 开发页）后，诊断收集器会自动运行。手机不需要打开控制台或游戏菜单。复现问题后保持页面在前台几秒，记下大致时间，再告知排查者。

## 数据怎么走

```text
游戏事件 / 每分钟心跳 / 错误
        │
        ▼
先异步写入 IndexedDB（浏览器自带的本地数据库）
        │  每两秒取一批，最多 20 条或编码后 48 KiB
        ▼
POST /__diagnostics/report
        │ 成功
        ▼
服务端追加到 .diagnostics/client-errors.jsonl 或 client-session.jsonl
        │
        ▼
客户端删除已确认的记录
```

IndexedDB 在刷新、页面被杀和 WebView 崩溃后仍保留记录。正常结束会写 `session-end`，并同步留一份应急副本，避免 IndexedDB 提交来不及；下次启动发现上一条会话没有结束标记时，补写 `session-recovered`，并把上次没传完的记录继续传出去。浏览器禁用 IndexedDB 时退回 `localStorage` 队列（写入合并到一秒一次）；进程可能立刻被杀的致命错误另存两行应急记录，下次启动补传。

`public/diagnostics.js` 在游戏模块之前执行，记录 `console.error`、`console.warn`、全局异常、未处理的 Promise 拒绝、页面资源错误和 WebGL 上下文丢失。每条记录都带：

- 会话 id、序号、墙上时间、页面启动后的毫秒数；
- 版本：游戏版本、包版本、内容版本、素材版本、构建模式；
- 设备：浏览器标识、屏幕与可视区、像素比、CPU 核数、设备内存档位、网络类型；
- 性能：帧率、最低帧率、长帧数、p95 帧耗时、堆内存、纹理数量、显卡型号、当前帧率上限和画面精度；
- 出错时的运行快照：场景、地图、坐标、血量、操作锁、战斗目标、AI 路径、剧情节点、音频状态等。

错误类记录默认附完整快照；其他记录默认只带少量字段，需要时在 `record` 第三个参数传 `true`。开战/收战、换图、存读档、心跳和高频事件都只带选定字段。

## 记哪些事件

- 生命周期：会话开始/结束/恢复、前后台切换、横竖屏、网络上下线、场景切换、菜单页面、启动阶段耗时。
- 地图与交互：进图/离图、交互目标、拾取、任务状态变化。
- 战斗：开战、每 5 秒一条聚合摘要（区间内的敌人数、命中数、造成和承受伤害、当前动作）、收战（整场累计的命中与伤害）。
- 剧情：选项、跳过耗时摘要。
- 存读档：自动存档成功/失败、读档开始/成功/失败。
- 内容与素材：内容加载失败、素材加载失败、超过 1 秒的慢资源。
- 性能：明显掉帧时上报（平均帧率低于目标值 80%，或最低值低于 50%，或一分钟内长帧达到 5 个；同一会话最多 5 分钟一次）。
- 心跳：游戏世界内每分钟一条精简状态；菜单里每 5 分钟一条。

所有错误类记录（类型以 `-error`、`-failed`、`-failure` 结尾，以及警告、WebGL 丢失、未处理拒绝和会话恢复）5 秒内同类只记第一条，被压掉的次数写在下一批的 `repeats` 里；合计每分钟最多记录 120 条，避免报错风暴挤掉其他记录。服务端返回 413 时先缩到单条确认，单条仍被拒绝才丢弃它；返回 400 视为协议或代理层面的全局问题，保留记录并退避一分钟，不会把本地积压清空。

## 服务端文件

| 文件 | 内容 | 轮转 |
|---|---|---|
| `.diagnostics/client-errors.jsonl` | 错误、警告、恢复、加载失败 | 2 MiB × 8 份 |
| `.diagnostics/client-session.jsonl` | 操作、心跳、战斗、性能 | 8 MiB × 11 份 |

每行是「客户端字段 + `receivedAt`」。服务端写盘成功后才按 `id` 记账，写失败时客户端重试仍能通过；请求体上限 64 KiB，单次最多 20 条。

## 怎么看

```bash
npm run diag:list                    # 最近 20 个会话
npm run diag:session -- <会话 id>    # 一个会话的完整时间线
tail -n 30 .diagnostics/client-errors.jsonl
```

`diag:list` 显示开始时间、时长、版本、地图、错误数、警告数、掉帧次数和是否正常结束。`diag:session` 按时间打印事件，错误行前面带 `!`，警告行带 `w`，心跳行显示帧率、长帧和堆内存。

浏览器内仍可用 `storyDiagnostics.export()` 导出记录；它现在返回 Promise，需要 `await`。

## 体积与边界

正常游玩大约每小时增加 0.5–1 MB 的记录，上传平均不到 0.2 KB/秒。IndexedDB 最多保留 5000 条或 7 天；降级 `localStorage` 队列最多 200 条，不做年龄清理；联网时几秒内就会清空。

不记录账号、密码、令牌、存档正文、文本输入框内容和界面上的玩家输入文字。逐帧数据（每一下伤害、每帧 AI）不直接记录，战斗细节按 5 秒聚合。

JavaScript 死循环、浏览器进程崩溃或系统强制结束页面，可能让最后几毫秒的记录来不及写入；没有收到报错不代表游戏没有异常。
