# 手机报错收集

刷新游戏入口（`https://catgo.online:4002/`）后，收集器会自动运行。手机不需要打开控制台或游戏菜单。复现卡住后保持页面在前台至少 8 秒，再告知排查者发生时间。

`public/diagnostics.js` 在游戏模块之前执行，记录 `console.error`、全局异常、未处理的 Promise 拒绝、页面资源错误和 WebGL 上下文丢失。图片与内容加载入口另记录已经被游戏捕获的加载错误。记录包含时间、设备浏览器、地图、主角位置与血量、当前攻击目标、操作锁、剧情节点、最后一帧阶段，以及 WebGL 上下文丢失和恢复。既有控制台输出和异常处理继续生效。

帧阶段使用 Phaser 的 `PRE_STEP`、`POST_STEP`、`POST_RENDER` 事件观察。页面在前台超过 5 秒没有下一帧时，独立计时器会产生 `frame-stalled` 记录。后台与恢复前台的等待不计入超时。这只证明没有出帧，不能直接证明根因；暂停或图形上下文丢失也可能产生该记录。

4002 的 HTTPS 入口（nginx 转发到 4004 静态服务）与 4003 开发服务都挂载 `POST /__diagnostics/report`，收到后追加到 `.diagnostics/client-errors.jsonl`，每行一条 JSON。文件达到 2 MiB 时轮转到 `client-errors.previous.jsonl`，这两个文件均被 Git 忽略。服务器在写入成功后才确认，发送失败保留手机上的待发缓存并定时重试；刷新页面也会重发。传输重试可能出现相同 `id` 的记录，排查时按 `id` 去重。

在项目根目录查看最新记录：

```bash
tail -n 30 .diagnostics/client-errors.jsonl
```

浏览器内可用 `storyDiagnostics.export()` 导出最近 32 条内存记录及待发记录。待发记录使用单独的 `inotia4.diagnostics.pending.v1` 缓存键，与游戏存档无关。只在页面启动、出错、停帧和少量关键流程节点（如剧情预取、重建、落位失败）记录，不逐帧上传；`?perf` 下每 30 秒记一条帧统计。客户端限制数量、对象深度与长度；服务器限制请求大小并轮转文件。

独立静态构建包含客户端收集器；只要 4004 的 `tools/serve-built.ts` 和 4002 的 nginx 在运行，上报端点就可用。若用其它静态服务器且没有接收接口，则只保留本地待发记录。JavaScript 死循环、浏览器进程崩溃或系统强制结束页面，可能让收集器也无法执行；没有收到报错不代表游戏没有异常。
