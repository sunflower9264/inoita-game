# 手机报错收集

刷新游戏入口（`https://catgo.online:4002/`）后，收集器会自动运行。手机不需要打开控制台或游戏菜单。复现报错后保持页面在前台几秒，再告知排查者发生时间。

`public/diagnostics.js` 在游戏模块之前执行，记录 `console.error`、全局异常、未处理的 Promise 拒绝、页面资源错误和 WebGL 上下文丢失。图片与内容加载入口另记录已经被游戏捕获的加载错误。记录包含时间、设备浏览器、地图、主角位置与血量、当前攻击目标、操作锁、剧情节点，以及 WebGL 上下文丢失和恢复。既有控制台输出和异常处理继续生效。

读档完成约 4 秒后记录 `load-audio-ready`，包含音频上下文状态、解锁与静音状态，以及正在播放或暂停的音轨，便于区分音频设备和音轨选择问题。

4003 开发页、4002 与 APK 每次点击跳过后写一条 `story-skip-summary`。`logicMs` 表示剧情逻辑推进到结束或必须停下的确认所用的毫秒数，`worldReadyMs` 表示相应画面或正式世界就绪的耗时，`unlockedMs` 表示归还操作权的耗时；都从点击时刻开始计算。`outcome` 为 `released`、`choice`、`quest-popup` 或 `cancelled`，分别表示交还操作权、停在选择、停在任务确认、取消播放。选择或确认期间的人工等待不计入跳过耗时，尚未经过的阶段为 `null`。摘要共用现有日志的游玩编号和时间，只带计时数据。对照同一存档的开场、同图和跨图剧情；已合成的人物外观应在换图和舞台之间复用。

4002 的 HTTPS 入口（nginx 转发到 4004 静态服务）与 4003 开发服务都挂载 `POST /__diagnostics/report`，收到后追加到 `.diagnostics/client-errors.jsonl`，每行一条 JSON。文件达到 2 MiB 时轮转：当前文件 → `client-errors.previous.jsonl` → `client-errors.previous-1..6.jsonl`，共保留 7 份（约 14 MiB），全部被 Git 忽略。旧客户端每帧重复上报的同一条检查点诊断，同一会话在同一张地图 60 秒内只保留第一条，避免把有用的记录挤出保留窗口。服务器在写入成功后才确认，发送失败保留手机上的待发缓存并定时重试；刷新页面也会重发。传输重试可能出现相同 `id` 的记录，排查时按 `id` 去重。

在项目根目录查看最新记录：

```bash
tail -n 30 .diagnostics/client-errors.jsonl
```

浏览器内可用 `storyDiagnostics.export()` 导出最近 32 条内存记录及待发记录。待发记录使用单独的 `inotia4.diagnostics.pending.v1` 缓存键，与游戏存档无关。只在页面启动、出错和少量关键流程节点（如跨图舞台预取、重建、落位失败）记录，不逐帧上传。客户端限制数量、对象深度与长度；服务器限制请求大小并轮转文件。

独立静态构建包含客户端收集器；只要 4004 的 `tools/serve-built.ts` 和 4002 的 nginx 在运行，上报端点就可用。若用其它静态服务器且没有接收接口，则只保留本地待发记录。JavaScript 死循环、浏览器进程崩溃或系统强制结束页面，可能让收集器也无法执行；没有收到报错不代表游戏没有异常。

跳过摘要的 `stages` 按点击后的毫秒记录素材开始、素材就绪、立绘、音效、外观和世界对象就绪；没有经过的阶段不出现。静默世界交接不准备后续立绘和演出音效。同名阶段记录最后一次经过的时刻。`story-entry-prefetch` 中 `missing` 表示本次真正需要补载的素材项数，0 表示全部复用。

穿脱装备完成后记录 `equipment-change-summary`：`elapsedMs` 是从点击到页面更新完成的耗时，`slot` 和 `member` 标明槽位与成员。实际合成外观时另记录 `outfit-compose-summary`，包含动作数 `clips`、部件绘制数 `parts`、最长连续工作时间 `longestWorkMs`；等待下一帧的时间不计入连续工作时间，命中缓存时不会产生新的合成摘要。对照同一存档换饰品、首次换武器/防具与切回穿过的装备，结合手机画面判断停顿是否改善。
