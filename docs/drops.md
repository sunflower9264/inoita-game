# 物品掉落机制

这份文档讲一件东西从怪物或箱子里掉出来，到躺在地上被捡走，中间每一步由谁决定。

规则数据在 [drops.json](../public/content/drops.json)，判定逻辑在 [drops.ts](../src/domain/drops.ts)，保底在 [loot-pity.ts](../src/domain/loot-pity.ts)，地面掉落在 [ground-loot.ts](../src/domain/ground-loot.ts)。

## 三十秒版本

```text
击杀 / 开箱 / 砸景物
        │  选一条规则（敌人自己的规则 / 宝箱类型 / 景物类型）
        ▼
掷 8 个槽位：金币 装备 消耗品 强化卷 材料 杂项 唯一 固定
        │  每个槽独立判定，整轮可重复 1～3 次
        ▼
命中的槽换成具体物品
        │  装备在这一步定格：稀有度 → 品级 → 孔 → 词条数值
        ▼
落到地面（嵌墙就挪到旁边）
        │
        ▼
走到 12 像素内自动捡进共享背包
```

## 一、谁在什么时候掷骰子

| 来源 | 位置 | 用哪条规则 |
|---|---|---|
| 打死敌人 | [world-combat.ts:1147–1157](../src/scenes/world-combat.ts#L1147-L1157) | 该敌人在 `drops.json` 里的规则 |
| 打碎灌木、坛子、木箱 | [world-combat.ts:1129–1132](../src/scenes/world-combat.ts#L1129-L1132) | `breakables` 里对应类型 |
| 打开宝箱 | [world-scene.ts:1133](../src/scenes/world-scene.ts#L1133) | `chests` 里普通、优良或 Boss |
| 完成任务条件的击杀 | [world-combat.ts:1161](../src/scenes/world-combat.ts#L1161) | `questItems` + 任务簿当前状态 |
| 剧情 `item-drop`、GM 发物品 | [session.ts:818](../src/domain/session.ts#L818) | 不走概率，直接落地 |

敌人和景物都是“被打死”这一个入口，区别只在于景物会额外检查要不要生成一只埋伏怪。

## 二、掉不掉：8 个独立槽位

槽位顺序固定为 `money equipment consumable upgrade crafting misc unique fixed`，见 [drops.ts:75](../src/domain/drops.ts#L75)。每个槽用同一个公式（[drops.ts:168–174](../src/domain/drops.ts#L168-L174)）：

```text
基础率 = floor( floor(2 × 配置值 × 怪物等级 / (怪物等级 + 玩家等级)) × (1000 + 全队物品加成) / 1000 )
实际率 = 基础率 + 保底加成
掷 1..9999，严格小于实际率才算命中
```

五点要记住：

- **配置值是万分比**。`3000` 是 30%，`100` 是 1%。宝箱怪、景物埋伏怪的 `spawn.chance` 写 100，意思就是约 1%，不是必出。
- **等级会缩放掉率**。怪物比玩家低级就衰减，高级就放大。玩家 60 级打 20 级怪，装备槽从 12% 掉到 6%；玩家 20 级打 60 级怪，从 12% 涨到 18%。
- **保底只能放大已经存在的槽**。配置值是 0 的槽，保底堆到 9999 也不会中；只有加成到 10000 才必中，这只有 Boss 首杀会用。
- **整轮可以重复**。规则的 `rolls` 是 1 或 3，重复的是整轮 8 个槽，所以 3 轮的金币槽能出三次金币。550 个敌人里 31 个是 3 轮。
- **全队物品加成目前是 0**。公式里的“全队物品加成”来自 `Session.partyItemChance`，现在没有任何地方赋值，所以乘数是 1；本文列出的掉率数字都不受它影响。

## 三、掉什么：逐槽选取

| 槽位 | 命中后怎么选 | 备注 |
|---|---|---|
| 金币 | 抽 50～100 的百分比，算 `3 + 4 × 等级 × 百分比 / 500`，再乘全局金币倍率 | 30 级怪 150～270 金币 |
| 消耗品 | 从 `consumable` 池按权重抽 | 支持按等级档位取（药水小中大特大） |
| 强化卷 | 从 `upgrade` 池抽 | 队伍加成 `scroll-drop` |
| 材料 | 从 `crafting` 池抽 | 队伍加成 `material-drop` |
| 杂项 | 从 `misc` 池抽 | |
| 装备 | 见第四节 | 队伍加成 `equipment-drop` |
| 唯一装备 | 从掉落等级不超过当前等级的唯一装备里等概率抽 | 队伍加成 `unique` 保底 |
| 固定物品 | 按权重 1000 抽 `fixed` 列表 | 不走等级 |

池子的每一项可以写 `{weight, item}`，也可以写 `{weight, tiers}` 按等级取不同物品；`item` 允许写成 `null`，表示这一项就是空手。所以槽命中了也不保证有东西，这由池数据决定。

金币的 10 倍来自 [economy.ts](../src/domain/economy.ts) 的 `MONEY_GAIN_MULTIPLIER`，只作用于掉落和任务金币；剧情 `money-give`、商店、GM 都不走它。

## 四、装备怎么挑，怎么定格

当选中的槽是装备时，[pickEquipment](../src/domain/drops.ts#L188-L209) 做两件事：定等级窗口，定类别。

```text
下界 = 等级 < 10 ? 1 : 等级 × 30%
在 [下界, 等级] 里掷两次取平均，再 +2 作为上沿
下沿 = max(1, max(上沿, 6) - 5)
类别 = 掷 1..100：< 20 武器，< 70 防具，其余饰品
```

窗口在等级附近很窄，通常只有 5 级。窗口内没有该类别候选就跨类别找，仍然没有就取最近的一件。

接下来是稀有度和品级。稀有度权重来自 `rarityProfiles`：

| 档 | 普通怪 | 精英 | Boss | 优良箱 | Boss 箱 |
|---|---|---|---|---|---|
| 0 普通 | 70% | 62% | 50% | 65% | 45% |
| 1 精良 | 23% | 28% | 32% | 27% | 33% |
| 2 稀有 | 7% | 10% | 18% | 8% | 22% |

品级在档内按权重抽：

- 稀有度 0 对应品级 0～3：生锈的 45%、陈旧的 30%、空的 20%、太古的 5%
- 稀有度 1 对应品级 4～6：锐利的 30%、打磨的 50%、工匠的 20%
- 稀有度 2 对应品级 7～9：钢铁 30%、钛金 50%、秘银 20%

稀有度 3、4 不会随机出现：唯一装备固定品级 10，epic 固定品级 11～13（品级表也定义了 14，但当前没有 epic 物品用到它）。随机装备的 `maxGrade` 是 9，所以即使把稀有度权重改非零，品级 10 以上仍会被过滤掉。

**章节带**（1-15、16-30、31-50、51-70、71-90、91-105）负责三件事：换稀有度权重、给装备等级封顶（15/30/50/70/90/105）、提供幸运值和缩放。当前配置里幸运和缩放都是中性值，实际起作用的只有封顶和权重表。

**数值在落地前就定好**：品级决定基础攻防、词条条数和孔上限；80% 概率开孔，1～4 孔按 35/30/20/15 抽，并且不超过品级允许的孔数（[character-stats.ts:409–412](../src/domain/character-stats.ts#L409-L412)）。唯一装备和固定物品直接用品级表里的静态档，不重掷、不开孔。

## 五、保底

保底在 [loot-pity.ts](../src/domain/loot-pity.ts) 里，跟着存档走，读档后继续累计。

- **两本账**：装备连续不出，装备槽每次 +60‰，上限 +900‰；稀有度 2 以上连续不出，唯一槽每次 +40‰，上限 +600‰。两个上限都等于连续 15 次空手。
- **按人记**：每个队员单独算，队友的运气不会互相抵消。
- **有等级窗口**：只有怪物等级 ≥ 该队员等级 − 10 才累计，刷低级怪堆不出保底。
- **出东西会清账**：出了装备清装备计数；出了稀有度 2 以上，两本账一起清。
- **宝箱单独记**：按宝箱类型（普通、优良、Boss）各记一本，只看开出来的东西里有没有装备。
- **Boss 首杀**：每个存档对每个 Boss 只触发一次，装备槽加成 10000（必中），并把稀有度下限提到 2，也就是至少出稀有档。每个存活队员各拿一份。

## 六、四种来源的差异

| 来源 | 等级从哪来 | 玩家等级怎么算 | 保底 | 品质下限 |
|---|---|---|---|---|
| 敌人 | 敌人规则里的等级 | 真实等级 | 有 | Boss 首杀为 2 |
| 宝箱 | 地图 `chestLevel`，没有就用 `lootLevel`，再没有就 1 | 封顶到箱等级 | 有 | 普通 0、优良 1、Boss 2 |
| 景物 | 地图 `lootLevel`，没有就用玩家等级 | 封顶到容器等级 | 无 | 无 |
| 任务道具 | 不参与等级公式，按 `threshold` 掷 1..99 | — | — | — |

“封顶到容器等级”是 [containerScaleLevel](../src/domain/drops.ts#L243-L245)：高级玩家开低级箱子时，玩家等级按箱子等级算。不这么做，等级公式会把掉率压到接近零，箱子就永远空。

宝箱和景物共用一套容器逻辑，但宝箱有品质下限，景物没有；景物里的木箱还能在队伍 `chest-quality` 加成下，以约 4.9% 概率升级成幸运箱，改用优良宝箱的掉落池。

任务道具是另一条线：只要任务在跑且还没交够数量，每次击杀按阈值掷一次，每只怪最多给一件，不随队伍人数翻倍。

## 七、落地与拾取

- **落点**：尸体或箱子的位置。如果落在墙里，就挪到最近的能站格子（8×8 像素盒子判定）。
- **地面表按存档会话保存**：换图、读档都还在；每张地图最多 64 件，超了淘汰最早生成的。
- **拾取范围 12 像素**，横纵各 12 像素的方形，不用走到正中。
- **背包共享**：谁捡都一样，捡到的东西进同一个包。
- **装备是实例**：落地瞬间就带好自己的品级、孔和词条数值，捡起来不会重掷。
- **魔法宝石**是战斗里生成的资源掉落，捡的时候交给战斗结算回蓝；不在战斗状态就留在原地。
- **剧情接管地图前**会把当前地图的掉落全部自动收掉，不会因为进剧情丢东西。
- **敌人掉落是个人掉落**：每个存活队员对同一只怪各掷一次，落点左右错开 ±5 像素；但地面共享，队友那份也能捡。

## 八、现状与数据缺口

这些是当前数据本身的特点，排查“为什么没掉”时先看这里：

- 103 个敌人配了 `fixed` 槽的概率，但 `fixed` 列表是空的，命中后什么也不掉。几个 Boss 的 `fixed: 500` 也属于这一类。
- `equipment` 槽的配置值只有 1200 和 3000 两种，所以敌人装备掉率基本只有 12%（普通）和 30%（Boss、多数精英）两档。
- `epic` 装备池有 76 件，但**没有随机掉落路径**：`pickEquipment` 只从武器、防具、饰品（`special`）取基础物品，`pickUnique` 只从 `unique` 取；随机装备的 `maxGrade` 是 9，稀有度 3/4 的权重在 `rarityProfiles` 和章节缩放里也都是 0。
- 紫装目前只有一条受限路径：4 个任务（`quest-494`、`quest-498`、`quest-501`、`quest-503`）奖励“被封印的武器盒/铠甲盒”，两个盒子的奖励表里共有 33 件 epic，单盒开出紫色的概率约 46%（武器盒）和 37.5%（铠甲盒）。其余 43 件 epic 在 `drops.json` 之外没有任何引用。
- 要让紫装进入随机掉落，不能只改稀有度权重；需要单独从 `equipment.epic` 池选取并按静态品级落地（和 unique 一样），再决定等级门槛、来源和保底。
- `Session.partyItemChance` 目前没有任何地方赋值，恒为 0，所以全队物品概率乘数这条加成没有实际效果。
- 宝箱内容在打开那一刻才掷，不是进图预演；进图预演只决定箱子是否出现、长什么样。
- 18 个敌人标了 `noNormalDrops`，它们的常规掉落直接跳过，但任务掉落仍然照常。

## 九、修改入口

| 想改什么 | 改哪里 |
|---|---|
| 掉率、池子物品、权重、章节带、保底参数 | [drops.json](../public/content/drops.json) |
| 判定顺序、公式、选取逻辑、掉落校验 | [drops.ts](../src/domain/drops.ts) |
| 让紫装进入随机掉落 | `drops.json` 的 `equipment.epic` + `drops.ts` 的选取路径（新增 epic 槽，或按等级拆分 unique 槽） |
| 保底累计与清账 | [loot-pity.ts](../src/domain/loot-pity.ts) |
| 地面数量上限、拾取半径、飞行掉落 | [ground-loot.ts](../src/domain/ground-loot.ts) |
| 装备品级、孔、词条数值 | [character-stats.ts](../src/domain/character-stats.ts)、[equipment-grade.ts](../src/domain/equipment-grade.ts) |
| 击杀、开箱、拾取的接线 | [world-combat.ts](../src/scenes/world-combat.ts)、[world-scene.ts](../src/scenes/world-scene.ts) |

改内容 JSON 后跑 `npm run validate:content`。`parseDrops` 会检查：宝箱轮数（普通 1 轮，其余 3 轮）、景物轮数固定 1 轮、池子每项权重 1～10000 且同类总权重不超过 10000、稀有度权重长度 5、章节带连续、v3 必须带稀有度档与保底配置。
