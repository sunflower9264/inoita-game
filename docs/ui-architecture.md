# 屏幕界面的职责

屏幕界面由 DOM、CSS 和必要的 SVG 绘制，地图角色、头顶血条与战斗表现由 Phaser 绘制。页面只调用现有领域规则，不重新计算加点、学习、交易或存档规则。

## 谁管理什么

| 入口 | 管理内容 |
| --- | --- |
| `StoryUI` | 游戏菜单导航、公共布局与文字设施、会话连接、输入作用域 |
| 各菜单页面 | 本页选择、草稿、确认、操作、节点和局部刷新 |
| `TitleMenuController` / `ClassSelectionPage` | 标题页面树和开局职业选择；场景只连接生命周期 |
| `FormalUiView` | 对白框、立绘、对白文字及剧情显示协调 |
| `FormalChoiceView` / `FormalModalView` | 选项及滚动；加载、阵亡和横屏提示 |
| `GameUI` | 剧情交互的状态、等待、完成和取消 |
| `WorldHud` | 一次地图访问的屏幕状态栏、摇杆、操作按钮、小地图、名称和帧率 |

游戏内页面绑定装配时的会话。页面依赖只传实际需要的内容、动作和显示服务；页面内部字段由页面自己修改。地图规则、战斗目标缓存和技能快捷栏计算继续在世界及领域层，界面接收显示结果。

## 离开与请求

玩家主动切页、换人或关闭菜单时，先处理人物加点草稿；确认成功或放弃草稿后继续原动作。确认失败保留草稿和确认按钮。释放会话时直接丢弃旧草稿并清理页面。

请求归发起页面管理。离开、替换请求或销毁后，旧结果不能写入新页面。`SavePage` 在关页时取消读档，并检查截图是否还属于当前保存请求。标题页和游戏内各持有一个 `SaveSlotRename`。输入结束时，它先检查本次改名是否仍在当前页面，再写入对应的手动槽。取消等待不撤销已经提交的领域操作。清理可以重复调用。

## 显示与输入

`formalPresentation` 根据当前状态计算可见内容，保留暂停、竖屏、加载、阵亡和世界重建的显示顺序。剧情跳过黑底与世界重建遮挡具有不同含义。正文或提示变化只刷新所属组件，保留选项按钮、输入和滚动。

原始键盘事件只由 `FormalUiScene` 转给已有输入路由，页面注册作用域。数字输入和文本输入先接收键盘，弹窗与菜单阻断地图操作。加点长按复用公共按钮，页面离开、输入卡打开和失焦时结束。

`WorldHud` 按地图访问装配和销毁，查询绑定固定会话，失效访问的输入不再执行。冷却继续随逻辑帧刷新；新建控件首次同步就采纳显隐状态，普通刷新保留既有节点。
