# src/domain

游戏规则的家：会话、剧情、战斗、物品、导航和存档都在这里，全部是纯 TypeScript。

## 文件

- 会话/剧情：`session.ts`、`story-director.ts`、`story-runtime.ts`、`story-graph.ts`、`story-condition.ts`、`story-scene.ts`、`story-script.ts`、`campaign.ts`、`scene-plan.ts`，以及同前缀的 `story-*.ts`、`scene-*.ts`；开发/测试模式开关与快照冻结在 `dev-mode.ts`，存档检查点的写时复制在 `playback-checkpoint.ts`。
- 挑战刷怪：`pressure-enemies.ts` 按主角等级筛选普通战斗怪并随机选择。
- 战斗：`combat-*.ts`、`battle.ts`、`action-*.ts`、`attack-*.ts`、`buff-*.ts`、`skill-*.ts`、`enemy-*.ts`；击杀奖励结算在 `combat-rewards.ts`。
- 队伍人数变化时按单位实际生命上限保持血量比例，主人派生的召唤物生命上限沿用召唤属性。
- 敌人的一次性技能在动作开始播放时计为已使用，追近目标期间保留使用机会。
- 冲锋备用落点逐像素检查身体、地形连通和沿途内容阻挡，停在最后一个可达点。
- 技能实际选择治疗目标时才构建治疗候选名单。
- 物品/背包：`items.ts`、`inventory.ts`、`bag.ts`、`drops.ts`、`loot-pity.ts`、`ground-loot.ts`、`crafting.ts`、`enhancement.ts`、`equipment-*.ts`、`shop.ts`、`money.ts`（金额拆分与显示文本）。
- 队伍/召唤：`party*.ts`、`companion-progression.ts`、`friendly-summon-ai.ts`、`summon-*.ts`；召唤物的归属分组、顶替、寿命与退场在 `summon-lifecycle.ts`。
- 导航/地图：`navigation.ts`、`navigation-world.ts`、`pathfinding.ts`、`path-budget.ts`、`walk-route.ts`、`map-placement.ts`、`minimap.ts`。
- 存档/状态：`save-game.ts`、`cloud-save.ts`（云存档账号、密码、槽位与锁定规则）、`state-application.ts`、`key-bindings.ts`、`control-skin.ts`、`legendary-weapon.ts`（拔剑判定、奖励与已拔状态）、`inns.ts`（旅店休息费用与恢复）。
- 任务/文本：`quest-*.ts`、`menu-panels.ts`、`text-markup.ts`、`description-text.ts`；世界交互判定在 `interaction.ts`；其余文件按前缀或符号搜索，例如 `combat-runtime.ts`、`story-entry.ts`。

## 规则

- 地图和剧情舞台按掉落、物品和敌人目录对象身份共享已校验掉落表；内容目录替换时重新校验。

- 进图剧情素材按可触发事件筛选，已完成且不可重复的事件不再加入；正在执行的剧情由入口单独加入。

- 战斗特效的 `viewport` 使用地图像素，`spawn.marginPx` 也以地图像素计；散布仍围绕施法者，随机数调用次数与伤害结算独立。

- 剧情播放器、检查点校验和预演按同一内容对象共享一份冻结脚本及节点、事件索引；任务定义沿用 `QuestBook` 的共享只读索引。每个执行器独立保存游标、队列和回滚状态，内容更新使用新的对象身份。

- 佣兵绕到敌人侧面前先检查起点和侧翼附近的可站网格；整片被挡就直接按攻击范围接敌。场景内每名佣兵每次最多搜索 48 个节点，未完成的路线下次继续。
- 固定或暂时不能移动的敌人检查技能可达性时，每批领取 8 个共享寻路节点，找到可攻击落点后立即停止领取；一次决策最多推进 128 个节点。预算耗尽保留搜索前沿，确认没有路径后才回家。已探索落点按 64 像素区域索引，用目标当前位置复核攻击距离，目标移动不重启搜索。更换目标、敌人移动、攻击范围变化或行为生命周期改变时释放旧搜索；可达结果最多保留 180 毫秒后重取通行快照。索引只属于当前搜索，返回、失去目标、取消和恢复时一并释放。
- 敌人等待寻路完成时，候选直线检查复用该次搜索的占位快照；起终点未变就复用检查结果，端点变化或新搜索重新检查。沿已完成路线迈步与实际物理移动仍读取实时碰撞。

- 会连续修改会话的入口用 `Session.batchNotifications`：它只把多次修改的通知合并成一次，失败不回滚。需要“要么全成、要么全退”的入口用 `Session.atomic(operation, touched)`，按 `touched` 声明实际会碰到的子系统懒抓快照；嵌套调用并入外层，失败只恢复这些子系统并丢弃待发通知，不给通知批次套整份会话快照。
- 剧情运行时快照不可变：`StoryRuntime` 的写入只替换数组和对象，`snapshot()` 直接返回引用，不做整份深拷贝。内部检查点走 `adoptTrusted`（版本、数组、ID 和重复的廉价检查；开发/测试模式再全量校验），读档、检查点恢复、GM 跳转和云存档走 `prepareRestore`。开发/测试模式用 `dev-mode.ts` 的 `freezeSnapshot` 冻结快照，生产热路径不冻结。
- `StoryDirector.onSkipProgress` 只报告跳过请求、最终逻辑提交、世界就绪、交还操作权与必须停下的确认；计时和日志由应用层接入。
- 剧情事件完成通知等世界投影成功后发出；投影失败重试成功时补发一次。
- 每段剧情对同一脚本的立绘和音效只发起一次准备；失败后允许重新准备，跳过只取消等待。
- 舞台快照中的 `mapEffect` 记录地图褪色开关，旧快照没有该字段时沿用当前效果。
- 跳过剧情只影响表现：`StoryDirector.prepare` 跳过时仍调用 `world.prepare`，为当前图和下一张确定地图发起预取，但跳过只结束等待，加载在后台继续，不阻塞剧情推进；同图舞台可补齐后续人物与战斗素材。立绘和音效同样发起预取但不阻塞推进；`choice` 和 `quest-popup` 之前调用 `presentation.flushStage`，先把逻辑舞台画出来再弹窗。任务、物品、标记、传送和检查点仍按原顺序提交。
- 本目录保持零 Phaser 依赖，也不 import `application`、`ui`、`rendering`、`scenes`、`debug`。
- 新规则写成纯函数或状态迁移，由 `application` 负责适配 Phaser、浏览器和磁盘。
- 击杀奖励结算（经验、普通/景物/付费道具/任务掉落、套装首杀与装备/黄装/紫装保底记录）在 `combat-rewards.ts` 算完；场景只负责播放表现、选择落点并写回会话。随机源由调用方传入，固定随机源即可在纯 Node 下复现。没有地图生成点的挑战模式临时怪通过 `pressureMode` 仍结算掉落，但不写地图击杀记录。
- 装备按怪物实际等级或容器等级筛选最近 15 级，全队击杀只产一份普通装备。黄装与紫装保底由全队共享，合格精英计 1 点，Boss 计 2 点，有对应等级的候选时累计。掉落封印盒保存来源等级并按该等级选取内容；旧盒子沿用原表。详见 `docs/drops.md`。
- 召唤物的分组、同主人顶替、寿命和退场规则在 `summon-lifecycle.ts`；场景保留 visual、物理体和名册实例，`WorldCombatState` 的序列化仍由 `combat-snapshot.ts` 负责。召唤物移除时清理会话里的血量/法力条目，检查点恢复重建同一批召唤物的路径保留这些条目。
- **主人离场时召唤物一起退场，旧档丢弃孤儿召唤。** `WorldEnemyRoster.refresh` 移除主人时同步移除它的召唤子树；旧存档如果已经留下找不到主人的召唤，`prepareCombatRestore` 会把召唤物、子召唤、分组、状态和仇恨记录一起剔除并记 `save-repaired-orphan-summon`，不让整次读档失败。
- 世界交互按宝箱 → 泉水 → 任务槽 → 服务 NPC → 商店 → 普通剧情的顺序在 `interaction.ts` 的 `resolveInteraction` 判定；场景只提供附近目标、任务槽和商店状态，并按返回的动作执行。朝向只用于交互前的转身表现，不参与能否交互的判定。
- **日志外任务只影响任务日志和面板，不影响场景标记。** `Session.markerActor` 和 `npcQuestSlot` 不按 `questBook.journalVisible()` 过滤；可接、进行中、待交付都要在头顶和小地图提示对应发布者或交付对象。进行中任务的 `talk` / `interact` 目标也算标记对象，目标没记满前显示 active 图标，记满后消失。日志外任务只是不写进任务日志的普通任务，不能因为日志里没有条目就让玩家找不到交付点或交互目标。
- 佣兵由 `party-follow.ts` 共享操控者行走轨迹，赶路纵队、停下 600ms 后恢复职责站位；站位必须从队长可达。归队用距离与持续远离共同判断：超过 192px 持续 900ms 且最近 1.2 秒净移动 48px、距离增加 32px，或超过 320px 持续 600ms，当前攻击收尾后跟队；回到 112px 内 600ms 后恢复协战。无进展 4 秒且至少两次恢复失败才请求拉回；等待寻路、暂停或不能移动时不累计。轨迹最多 128 点，跟随决策间隔 120ms，单次寻路最多领取 48 节点，直路不申请寻路。自动施法频率、技能消耗和原有战斗侧翼规则保持一致。
- **跟随左右按当前操控者重排。** `Party.followSlotOf(leaderId, id)` 去掉操控者后按上阵顺序分左右；`slotOf` 只表示名册固定槽。主角不在 `slots` 里，固定 `slotOf('player')` 返回 `undefined`，不能再拿它当跟随侧位，否则主角会和槽位 0 的佣兵站到同一点。
- 寻路的地形在整图生命周期内只读共享。佣兵跟随和追敌时，追敌搜索只取一次人物占位；跟随搜索只读取固定机关索引，短路段实时检查动态占位，按 16 像素网格查附近的角色，再用 `overlapsAt` 判断是否相撞。沿路线迈步前仍查实时占位。搜索预算按发起者公平分配，避免队伍 AI 先领走整帧预算、后续单位饿死；友好召唤物的跨帧搜索也领同一份共享预算，领取为 0 时保留搜索前沿、下一逻辑帧再试；没有技能时不要算 `reachableNow`。
- 寻路扩展邻点时先排除越界和已经有更短路线的点，再检查地形与身体占位；搜索使用同一份冻结占位，保留路线枚举顺序和每帧节点预算。格子编号和通行缓存用整数键；查询提供 `canStandXY` 时不再为每个采样点创建对象，邻居枚举顺序和堆比较规则保持不变，路径顺序用例会固定它。
- 追击和跟随先查直线：直线可走就不创建寻路任务，直接朝目标移动；目标移动、身体卡住或直线被挡时再回到 A*。直线检查的终点停在目标身体前，避免目标自己的占位把直线判成墙；检查结果按起终点缓存，不每逻辑帧重扫。
- 同一目标至少 3 个敌人追击时共享一张流场：流场只把地形和内容机关当障碍，会移动的单位交给物理分离；目标移动超过 16 像素或 800 毫秒没有请求就重算，最多同时保留 4 张。流场建完前各单位继续走 A*，建好后只读自己格子的方向；身体卡住时回到 A*。
- 技能位移的落点必须整个身体站得住，并与施法者处于同一块地形连通区域；目标附近找不到时朝目标方向退到最远可站点，原地也站不住才取消。可走性复核只把地形和内容实体当障碍，敌我单位会移动，不算永久隔断。技能位移的落点复核用 `sameTerrainRegion` 加直线内容检查：瞬移只要求同地形连通和落点整盒站得住；8 像素突进逐像素检查整盒，已经覆盖沿途；不要再为这些位移跑全路线 A\*。冲锋选点用整数格子键和小堆，不每轮重排开放表；同一次选点内的可站/可达结果要缓存。
- 不会自己移动的内容机关（火焰、路障、宝箱）由 `NavigationActor.content` 标记；卡住自愈只处理这类实体，队伍单位与敌人的贴身接触仍交给物理分离，不能每帧把角色传走。
- 内容机关独立登记；注册用途变化时调用 `NavigationWorld.refreshActor`，注销时同步移除。机关位置、显隐与碰撞盒在查询时读取当前值。
- 背包的 `remove`/`consume` 直接操作目标容器并增量维护计数，不复制全部散装实例、不重建整张计数表；可堆叠、强化、宝石、词条和绑定技能的合并规则保持不变。
- 金额一律以铜币存储；对玩家展示时用 `money.ts` 的 `moneyText` 或 `splitMoney`，不要直接把裸数字写成「金币」。
- `SAVE_FORMAT` 当前是 54；摘要里的 `screenshot` 是保存时的游戏画面缩略图（JPEG data URL），旧档没有时界面留空。改存档结构或校验口径时把版本加一，并在 `src/application/saved-game.ts` 补迁移和旧档测试。升级链覆盖的旧档正常读取；比升级链更早的档案显示为空槽。
- 保留道具（原版付费道具）由 `items.ts` 的 `reservedItems` 标记，普通掉落和商店继续过滤；被封印技能书是例外，它同时保留在保留掉落通道，并允许从普通掉落和商店获取；任务奖励可以发放配方书，其他保留道具仍拒绝。配方书配方在学会后可在融合器合成（结果仍是保留道具），未学会的配方和结果为保留道具的常备配方仍隐藏；原版配方表本来就常驻的三条药水配方（再生药水（特大）、元气恢复药水、卓越灵药）用 `allowReservedResult` 显式放行，可以正常合成；`drops.ts` 的 `reservedDrops` 与融合器任务奖励是配方书的两个获取来源。一次性领取记录和解锁保底在会话状态 `reservedDrops` 里；旧档只补空状态和已经拥有的一次性道具领取记录，不清理已有物品。
- **剧情伙伴离队时装备退回背包，并按实例记录退役装备表。** 重新入队先穿回同一批实例，玩家已经卖掉或规则不再满足的槽位才补发初始装备；不能每次入队都新建一套，否则剧本里反复离队、归队会复制可出售的装备。退役表随背包存档，旧档缺省为空。
- 剧情人物装备由 `items.ts` 的 `storyEquipment` 标记；普通掉落、商店、合成、任务奖励、初始物品和商人货架统一用 `blockedNormalAcquisitionIds` 过滤，保留掉落通道继续只用 `reservedAcquisitionIds`。剧情 `equip`/`item-give` 可以使用这些装备，`item-drop` 不允许。
- 敌人的 `specialRank` 直接来自原版怪物记录分类（0 普通，1/2/3 特殊怪），只决定小地图星标和目标面板三星；掉落分层 `threat` 不是显示分类，不要拿它代替。
- 同 id 物品只有在目录 `stackable` 为真、且实例没有强化、宝石、词条和上锁时才合并；绑定技能不阻止合并，但它属于合并键：同 id 同技能的实例合并，不同技能分开存放。读档时把旧档里分散的可合并实例收拢成一条：数量相加，保留一条实例，并更新全部页与分类袋的格位引用。
- 存档和检查点只在队伍至少一人活着时记录；读旧档发现全队 0 血时，先把上阵队伍恢复到满状态再进世界。
- 古老武器把地图等级 0 兜底成 1（体验版偏离原版“除零必失败”）。
- 普通地面掉落不跨图：进入另一张地图时清掉其他地图的非任务掉落；`category` 为 `quest` 的物品（含剧情 `item-drop`）留在原图，任务生成点自己的掉落仍由 `QuestItemGenerators` 清理。
- 地面掉落只推进仍在飞行的对象。`collectNearby` 接收可拾取条件版本后，位置、掉落版本和接收条件都未改变时跳过扫描；背包、队员或资源变化必须更新该条件版本，落地与恢复自动使掉落检查失效。
- **绘制和只读查询直接读本图掉落。** `GroundLootView`、结算保底入参这类只读调用用 `dropsOnMap`，不复制整张表；需要离开 store 的副本（存档、返回给调用方）才用 `forMap`。
- 进图落点常贴着回程出口；出口要等角色累计走过 80 像素才重新武装，避免贴门一步就弹回上一张图。
- 恢复泉水的回血、回蓝按每名存活的上阵队员自己的上限结算，数值夹到上限；正面状态同样给所有存活上阵队员。药水病、药效减半、技能封印和攻升防降的疯癫只给喝下泉水的人。技能点只给主角；出怪与队伍组成无关。
- 组队技能 122「被选择的英雄」在基础拔剑奖励后额外掷一次 uniqueBonus/1000；命中把普通装备或空手失败升级为唯一物品，已经是唯一物品则不重复判定。
- 选择事件按选择标识的写入次数判断：同一个选项再次被选中也算一次新的发生，不能只比较选择值；一次选择只执行一条选择事件，新的选择作为下一次发生排队。
- 剧情、任务、事件 ID 是存档引用，只新增不改名；要改名就配套迁移。
- 云存档的账号/密码/槽位校验和锁定时长只在 `cloud-save.ts` 写一份，服务端复用同一份规则；云端保存不改 `SAVE_FORMAT`。
- 缓存失效用只读修订号：`PartyRoster.groupModifierVersion`、`CombatConditions.revision`、`Session.choiceWriteRevision`/`receiptRevision`/`enemyRevision`、`StoryWorld.encounterRevision`、`LegendaryWeapons.revision`。新增 mutation 入口时同步推进对应修订号；这些字段不写入存档。
- 伤害数字的帧序列只由帧数和保持帧数决定，`digitSequence` 直接复用缓存数组；每次命中的反馈计划只算一遍，选择素材、闪光和数字共用同一份结果。
- 自动存档的持久快照按子系统版本复用深拷贝（`captureStateWith(..., true)`）；读档/回滚时清空缓存。`captureState()` 的检查点路径保持每次新克隆。
- 任务奖励收据（结算时写下的一次奖励记录）每个任务只保留周期最新的一张；写入和读档恢复都按任务取最新周期，旧存档里同一任务的旧轮次在恢复时丢弃。防重复结算看周期有没有前进。
- 可破坏物生成记录按完整 id 覆盖；旧档读入时去重，并清理已永久死亡且不会再生成的 `breakable:` 记录，`chest:`/`spring:` 的永久死亡记录保留。
- 仇恨账本以 owner→source 索引为准，记录数组只用于快照与容量淘汰；增删必须同时维护两边。
- 剧情世界的进行中遭遇以 `StoryWorldState` 的 active 索引为准，`encounters` 表只用于历史、快照和完整状态查询；新增、结算和整份恢复必须同时维护索引，每帧读取只走索引。
- 地图敌人生成点索引按投影复用；任务、剧情、生成资格或名册身份变化及复活期限到达后才重新计算增删。`Session.enemySpawnRevision` 只跟踪死亡期限与恢复/回滚，血量和法力变化继续推进存档用的 `enemyRevision`，不会触发生成扫描。
- 人物页大立绘按来源取图：主角和剧情同伴用 `character.portraits` 的 252×271 立绘，佣兵用 `character.classPortraits` 的职业 252×271 立绘；小头像统一用 `party-class-*` 或 `character-party-*`。`memberArt` 是唯一入口。
- 单元测试写在 `tests/*.test.ts`。

## 验证

- `npm test -- tests/session.test.ts` 覆盖会话与剧情状态；`npm test -- tests/save-game.test.ts` 覆盖存档结构与格式号。

- 放逐成功时同步删除该成员的掉落保底计数；移入预备队保持计数。恢复存档后按名册保留主角和仍拥有成员的计数。

- `CombatConditions.activeAppearances()` 只列潜行、头顶标记、身体颜色和循环特效的角色；状态变动使对应角色的表现与状态数组失效。无状态读取共用空数组，暂停期间复用循环帧描述；恢复和清空同时清理派生缓存。
- `CombatConditions.activeBuffReactions()` 为结算提供按角色复用的只读反应定义；状态与增益变化、恢复和清空使缓存失效。计时和叠层写入独立的运行状态，寿命换算创建新定义；对外 `buffReactions()` 继续返回隔离副本。
- `CombatConditions.update` 在没有状态和增益时直接返回；有按时间增长的蓝耗修正（`attributeRamps` 指向 `manaCostRate` 或 `manaCostReductionRate`）时，`hasManaCostAttributeRamp` 必须返回真，调用方不得缓存蓝耗。
- `CombatController.basicAttackRange` 读取已解析普攻的接近距离；换装备通过 `setBasicAttack` 更新，决策查询只叠加实时射程加成。
- 手动攻击性技能完整结束后，普攻连打先尝试一次：有目标沿用目标，无目标按普攻规则搜索；搜索不到或玩家移动时停止。自身、队友和召唤技能不启动连打。

- `story-preparation.ts` 从当前节点和返回栈沿 next/call/end 查找下一张确定地图；选择、任务确认、条件分支及战斗等待截断预测，读取过程不执行命令。

- 装备实例的 `locked` 由玩家手动设置，只阻止出售与丢弃；`Bag.setLocked` 推进背包版本。清理装备按独立品质集合与等级上限筛选，排除穿戴、锁定、强化、宝石和混沌装备；确认提交重新校验报价并使用出售事务。

- 佣兵每级获得 5 个可分配能力点；旧档保留已有自动成长，重置后按全部等级计算。

- 演员快照用可选 storyPoseHold 记录剧情动作的收尾方式；转向保留动作与进度，走路、重新出场及新动作接管旧姿态。

- 神灯召唤由 `lamp-merchant.ts` 将扣除一枚道具与创建本次进图的商人实体一起提交；独立实体共用商店库存，离图清理，同图读档恢复。

- 佣兵技能先按角色等级成长到招募时生成的自然上限，再用技能书提升至技能的最高等级；每名佣兵的用书等级独立保存。被封印技能书打开后变成绑定技能的解锁书：同职业佣兵未学会该技能时可以从 1 级解锁，已学会的佣兵不能使用；解锁书使用后不消耗，可以继续给其他同职业佣兵使用。同一技能的解锁书同时只持有一本：开封时跳过背包里已有解锁书的技能，本职业技能都已有书时拒绝开封并保留封印书。
